🧹 MaidLedger — 數據庫架構與資料流程

更新日期：2026-05-23 | 來源：supabase/migrations/

🎯 統一 Schema 目標：Chat 和 Scan 寫入完全相同的 tables——只是輸入方式不同。所有收據條目都經過：receipts → receipt_items → master_products + product_aliases，同時更新 shops + shop_aliases 和 price_history。

📥 幫手 App 輸入流程（Chat）

  1. 用戶輸入：「魚 30蚊」
  2. → chat-parser Edge Function（LLM 解析）
  3. → chat-orchestrate Edge Function（協調者）
  4. → receipt-writer createFromChat → receipts
  5. → receipt-writer writeItemsFromChat → receipt_items
  6. → shop-manager upsert → shops + shop_aliases（僅當用戶提供店名）
  7. → receipt-writer writeShopLink（僅當店名匹配成功）
  8. → product-manager upsert → master_products + product_aliases
  9. → receipt-writer writePriceHistory → price_history

📷 幫手 App 輸入流程（Scan）

  1. 用戶拍攝圖片 → ML Kit OCR
  2. → receipt-parse Edge Function（LLM 解析）
  3. → DB Trigger → receipt-orchestrate（協調者）
  4. → receipt-writer → receipts + receipt_items
  5. → shop-manager → shops + shop_aliases
  6. → product-manager → master_products + product_aliases
  7. → receipt-writer writePriceHistory → price_history
  8. → Supabase Realtime → 通知僱主

🕷️ 爬蟲流程

  1. Python + Playwright 抓取 HKTVmall / 惠康 / 百佳
  2. → shops（insert/update）
  3. → shop_aliases（insert）
  4. → master_products（insert/update）
  5. → product_aliases（insert）
  6. → price_history（insert，source_type='scraper'）

🔔 即時通知流程

  1. Helper 寫入 receipts → Supabase Realtime 監聽
  2. → notification-broadcast Edge Function
  3. → 查詢僱主 device token
  4. → 發送 Firebase FCM / APNs 推送

🔑 為什麼某些 item 沒有建立 master_product？

情況原因狀態
extracted_name 在 product_aliases 有 exact match不會建立新的，已經有 master_product_id✅ 預期行為
extracted_name 在 master_products 有 ILIKE match會建立 product_alias，但唔會建立新的 master_product✅ 預期行為
extracted_name 完全新，無任何 match應建立 master_product + product_alias✅ Bug 1+2 隔離後應正常
LLM 無法拆出通用 product nameextracted_name 為 null，回退到 item_name✅ 回退機制

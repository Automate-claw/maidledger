❌ Critical Issues

❌ price_history.unit = free-text "件"

→ 同一 product 有 "件", "500g", "斤", "2件" → 無法 cross-record 比較

→ selectedWeights 傳遞鏈斷 → user 揀 500g 但寫入 "件"

Fix: 加 weight_g, unit_display, price_per_kg, price_per_pcs

❌ receipt_items 有大量 derived data 冗餘

同時存在：unit_price + line_total 和 actual_price + price_per_gram + cc_price_per_gram + weight_grams

→ price_history 又重新寫一次 (unit, original_price, total_paid)

→ 同一筆交易資料寫咗3個地方，沒有單一 source of truth

Fix: 統一到 price_history，receipt_items 只做 raw storage

❌ receipt_items.item_raw_text 幾乎全部 NULL

55 rows，但呢個 column 從來冇被寫入 → 應該移除或確保有價值先留

⚠️ Structural Issues

⚠️ receipts.parsed_data / items (jsonb) — 用途？

兩個 jsonb column，但 receipt_items 已經係正規化 table

→ 呢啲 jsonb 係暂存？備份？從未清理？

⚠️ expense_summaries — 冗餘 aggregate

month + category + total_amount + transaction_count

→ 可以由 receipts + receipt_items 即時查出，唔使預先 aggregate

→ 每次新 receipt 都要更新 summary，增加 write complexity

→ 但可能係出於效能考量（老闆要睇月結）

⚠️ price_data — 爬蟲舊表？

→ 兩張都係價格參考表，重疊

需要確認代碼有冇用到 default_unit

✅ Data Duplication Map

同一筆消費的數據分佈：

receipts:          amount, store_name, location, transaction_date
    ↓
receipt_items:     item_name, unit_price, line_total, weight_grams, extracted_spec, actual_price
    ↓
price_history:     price, unit, original_price, total_paid, source_receipt_id

→ receipt_items.unit_price  = price_history.price (重複)
→ receipt_items.line_total  = receipt.amount (部分重複)  
→ receipt_items.weight_grams = price_history (未寫入，TODO)
→ receipt_items.extracted_spec → price_history.unit (混乱)

建議：
  receipt_items 只保留：item_name, qty, unit_price (raw)
  price_history 完整記錄每次交易的標準化價格記錄
  expense_summaries 如果係效能需要可以保留，但月結可以即時算
